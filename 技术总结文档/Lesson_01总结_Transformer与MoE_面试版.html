Lesson 1：Transformer 与 MoE

大白话理解 + 代码验证 + LLM 面试复习版｜面向有计算机硕士基础的学习者

先记住一句话： Transformer 本质上是一个“对序列做上下文建模”的神经网络。它把 token 变成向量，用 Attention 计算“当前 token 应该参考哪些 token”，再通过 FFN 做非线性变换；重复很多层后，用输出头预测下一个 token。MoE 则把 FFN 换成多个专家，并让路由器为每个 token 只挑少数专家工作。

二、Transformer 的全局心智模型

文本 → tokenizer → token IDs → Embedding + Position → Attention（跨 token 交换信息） → FFN（逐 token 做非线性特征变换） → 残差连接 + LayerNorm → 重复 N 层 → Linear 输出 logits → Softmax / 采样下一个 token

面试时不要只背“Transformer 没有 RNN”。更完整的表述是：它用 Attention 直接建立任意两个位置之间的依赖，训练时可以对整个序列并行计算；代价是标准自注意力在序列长度为 S 时，注意力矩阵的时间和显存复杂度大致为 O(S²)。

三、从 token 到向量

1. Tokenizer、ID 与 BPE

模型不能直接理解字符串。Tokenizer 先把文本切成 token，再把 token 映射成整数 ID。课程代码里的 BPE 是教学版：从字符开始，反复统计最常见的相邻 token 对并合并。真实 LLM 使用更成熟的 BPE、Unigram 或 SentencePiece 变体，通常还会处理字节、未知字符、特殊 token 和词表边界。

面试重点：ID 只是查表的索引，不具有大小关系；真正进入网络的是 embedding 向量。中文不一定“一字一个 token”，英文也不一定“一词一个 token”。

2. Embedding

Embedding 可以看作一个形状为 [vocab_size, d_model] 的可训练查找表。输入 ID 是整数，输出是对应行的向量。课程实现还乘了 sqrt(d_model)，这是原始 Transformer 中常见的缩放方式，用于让 embedding 的数值尺度与后续网络更匹配。

常见追问：为什么不用 one-hot？
one-hot 维度等于词表大小且极度稀疏；Embedding 通过查表得到低维稠密向量，参数和计算都更实用，并且能通过训练表达词之间的语义关系。

3. 位置编码

Attention 本身对输入排列具有置换等变倾向：如果没有额外信息，模型不知道第一个 token 和第五个 token 的区别。因此需要把位置信息加到 token 表示中。课程代码实现的是经典正弦/余弦位置编码：

PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))

现代 LLM 常见的是 RoPE、ALiBi 等相对位置方法。面试回答时可以补一句：绝对位置编码直接把位置向量加到 hidden state；RoPE 则通过旋转 Q/K，使注意力内积带上相对位置信息。

四、Self-Attention：让 token 互相“查资料”

对每个 token，模型通过三个线性投影得到 Query、Key、Value：

Q = XWQ，K = XWK，V = XWV Attention(Q,K,V) = softmax(QKᵀ / √d_k) V
  • Query：当前 token 想找什么信息。
  • Key：每个 token 能提供什么信息，用来和 Query 匹配。
  • Value：真正被加权汇总的内容。
  • 缩放 √d_k：防止 QKᵀ 数值随维度变大，导致 softmax 过度尖锐、梯度变差。
  • softmax：把匹配分数变成权重；每个 Query 对所有 Key 的权重和为 1。

若输入 X 形状为 [B,S,D]，单头注意力的核心分数矩阵形状是 [B,S,S]。第 i 行第 j 列，表示位置 i 的 Query 对位置 j 的 Key 的关注程度。

Multi-Head Attention

多头不是简单重复同一个 Attention，而是把 D 维 hidden state 切成多个子空间，每个头学习不同关系，例如指代、语法、局部搭配或长距离依赖。课程代码中典型配置是 D=512、heads=8，则每个头的维度是 d_k=64。

[B,S,D] → [B,heads,S,D/heads] 每个头独立计算 Attention → 拼接回 [B,S,D] → Wo 投影

工程提醒：实现多头时最容易出错的是 view/reshape 和 transpose 的维度顺序。建议每次都写清楚张量形状，而不是只看代码能不能跑。

五、FFN、残差和 LayerNorm

1. FFN 为什么重要

Attention 主要负责 token 之间的信息混合；FFN 主要负责对每个 token 的表示做更深的特征变换。典型形式是：

FFN(x) = W₂ · σ(W₁x + b₁) + b₂

中间维度通常比 hidden size 大，激活函数提供非线性，否则多层线性层可以合并成一层线性变换。现代 LLM 常把 ReLU 换成 GELU、SwiGLU 等。

2. 残差连接与 LayerNorm

残差连接给信息和梯度提供一条更短的通路：y = x + F(x)。LayerNorm 则在特征维度上标准化每个 token 的表示，减轻数值漂移，让深层训练更稳定。

形式公式理解
Post-LNy = LN(x + F(x))原始 Transformer 常见；Add 后 Norm
Pre-LNy = x + F(LN(x))现代大模型更常见；残差通路更直接，深层通常更易训练

六、Encoder、Decoder 与 LLM 架构

Encoder-only：BERT
双向看上下文，适合理解任务：分类、检索向量、序列标注。通常使用特殊的 [CLS] 表示汇总信息。
Decoder-only：GPT、Qwen、Llama
使用 causal mask，当前位置不能看到未来 token；训练时可并行计算 mask 后的序列，推理时按 token 自回归生成。
Encoder-Decoder：T5
Encoder 双向理解输入，Decoder 用 masked self-attention 生成输出，并通过 cross-attention 读取 Encoder 的 K/V。
为什么 LLM 多用 Decoder-only
训练目标统一为 next-token prediction，规模化简单；同一套模型既能续写，也能通过提示词完成问答、摘要、代码生成等任务。

七、MoE：把一个大 FFN 拆成多个专家

1. 直观理解

普通 Transformer 的每个 token 都经过同一个 FFN。MoE 准备多个 FFN 专家，再用 Router 根据 token 的 hidden state 计算路由分数，选择 Top-K 个专家，最后按权重加权合并结果。

hidden states → Router → Top-K experts → 加权求和 → 输出 hidden states

2. 课程代码实现了什么

  • BasicMOE：演示多个 Expert 和 Gate 的基本结构。它会计算所有专家，再加权合并，更偏教学示例，不是严格的稀疏实现。
  • SparseMOE：对每个 token 选择 Top-K 专家；通过 expert_mask 找到每个专家负责的 token，再用 index_add_ 把结果写回原 token 位置。
  • ShareExpertMOE：在稀疏专家之外增加共享专家。共享路径让所有 token 都获得一部分通用能力，稀疏路径负责更专业的模式。

3. 面试中最容易说错的点

MoE 不是“参数量和计算量都变小”。更准确地说：总参数量可以变大，但每个 token 激活的专家数量有限，因此单 token 的计算量可以控制在较低水平。实际系统还要付出 token dispatch、跨 GPU 通信、负载不均衡和显存占用的代价。

真实 MoE 通常还需要负载均衡机制，例如 router auxiliary loss、capacity limit 或更复杂的路由策略；本课程代码重点是理解前向传播和 token dispatch，没有完整实现工业级训练稳定性方案。

九、面试高频问答

Q1：为什么 Transformer 比 RNN 更适合大规模训练？
A：RNN 按时间步串行，难以充分利用 GPU；Transformer 在训练阶段可对整个序列并行计算，并通过 Attention 直接建立长距离依赖。代价是标准 Attention 的 O(S²) 复杂度。

Q2：Q、K、V 分别是什么？
A：Q 表示当前查询需求，K 表示每个位置可被匹配的索引，V 表示被聚合的内容。QKᵀ 产生相关性，softmax 后对 V 加权。

Q3：为什么要除以 sqrt(d_k)？
A：维度增大时点积方差增大，softmax 容易饱和，梯度变小；缩放可以把分数控制在更合适的范围。

Q4：为什么要多头？
A：不同头可以在不同表示子空间关注不同关系；多个头拼接后提高表达能力，而不是单个头承担所有关系。

Q5：为什么需要位置编码？
A：Attention 单独看 token 集合时缺少顺序信息，位置编码/位置机制让模型区分先后顺序，并建模相对距离。

Q6：Pre-LN 和 Post-LN 怎么选？
A：Post-LN 是原始 Transformer 形式；Pre-LN 让残差通路更直接，通常更利于深层大模型训练。具体还要结合模型结构和训练配置。

Q7：MoE 为什么能扩大参数规模又控制计算量？
A：专家总数增加了总参数，但 Router 对每个 token 只激活 Top-K 个专家，所以 active parameters 和计算量不必随总专家数同比增加；实际还要考虑通信和负载均衡。

Q8：训练时为什么 Decoder-only 可以并行，生成时却是串行？
A：训练阶段整段真实序列已知，可以用 causal mask 一次算出每个位置的 next-token loss；推理阶段下一个 token 依赖上一步生成结果，因此天然自回归。

Q9：KV Cache 解决什么问题？
A：生成第 t 个 token 时，历史 token 的 K/V 不变，可以缓存并复用，避免每一步重复计算历史部分；代价是显存占用随 batch、层数、序列长度增长。

Q10：如何定位 Transformer 实现的 shape bug？
A：从 [B,S,D] 开始逐层记录形状，重点检查 head 拆分、transpose、mask 广播、contiguous/reshape，以及输出重新合并是否回到 [B,S,D]。
