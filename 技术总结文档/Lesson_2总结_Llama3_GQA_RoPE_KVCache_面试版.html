Lesson 2：Llama 3、GQA、RoPE 与 KV Cache

从真实 Llama 3 8B 权重出发的代码理解 + 面试复习版

先记住主线： Llama 3 仍然是 Decoder-only Transformer。它用 tokenizer 把文本变成 token，用 Embedding 得到向量；每一层通过 RMSNorm、带 RoPE 的 GQA、残差连接和 SwiGLU 逐步更新 hidden state；最后经过 RMSNorm 和输出投影预测下一个 token。推理时用 KV Cache 避免重复计算历史 token 的 Key/Value。

一句面试回答： Llama 3 8B 是 32 层、hidden size 4096 的 dense Decoder-only Transformer，采用 RMSNorm、SwiGLU、RoPE 和 32Q/8KV 的 GQA，以降低推理阶段 KV Cache 的显存和通信压力。

三、从文本到下一个 token

文本 → tiktoken/BPE → token IDs → Token Embedding → 32 层 Transformer Block
每层：RMSNorm → GQA + RoPE → 残差 → RMSNorm → SwiGLU FFN → 残差
→ Final RMSNorm → Output Projection → logits → argmax / sampling → 下一个 token

1. Tokenizer

Notebook 使用 Llama 3 的 tokenizer.model，通过 tiktoken.Encoding 加载 mergeable ranks 和 special tokens。Tokenizer 把字符串转换为整数 ID；ID 本身没有大小关系，真正进入模型的是对应的 embedding 行向量。

不要把 tokenizer 和 embedding 混为一谈：tokenizer 是离散的文本压缩/切分规则，embedding 是模型里可训练的向量查找表。

2. Embedding

输入 token 序列形状为 [S]，经过 Embedding 后变成 [S,4096]。课程示例的 prompt 有 17 个 token，因此得到：

tokens: [17] → token_embeddings_unnormalized: [17, 4096]

四、RMSNorm：Llama 选择的归一化

RMSNorm(x) = x / sqrt(mean(x²) + ε) ⊙ g

其中 g 是可训练的缩放参数。RMSNorm 不像 LayerNorm 那样先减均值，因此少了均值计算，结构更简单，适合大模型训练和推理。

对比LayerNormRMSNorm
是否减均值是否
归一化方式基于均值和方差基于均方根
工程特点表达完整但计算略复杂计算更简单，Llama 系列常用

五、RoPE：把位置信息放进 Q/K 的旋转

Self-Attention 如果只看到一组 token 向量，无法天然知道 token 的顺序。RoPE 不直接把一个位置向量加到 embedding 上，而是对 Q 和 K 的二维分量对进行位置相关的旋转。

对每一对 (x₂ᵢ, x₂ᵢ₊₁)：
[x'₂ᵢ, x'₂ᵢ₊₁] = [x₂ᵢ cos(mθᵢ) - x₂ᵢ₊₁ sin(mθᵢ), x₂ᵢ sin(mθᵢ) + x₂ᵢ₊₁ cos(mθᵢ)]
θᵢ = θ_base^(-2i / d)

代码把相邻两个维度视为一个复数，用复数乘法完成旋转，再还原成实数张量。旋转同时作用于 Q、K，最终点积中会自然携带相对位置信息。

面试怎么解释 RoPE

  • 它是对 Q/K 的位置相关旋转，而不是简单拼接一个 position embedding。
  • 旋转不改变向量范数，位置影响主要体现在 QKᵀ 的相对相位上。
  • RoPE 让注意力分数能够表达相对距离；Llama 3 把 base frequency 提高到 500000，以支持更长上下文的训练/扩展。
  • 长上下文并不是只改一个 θ 就完成，还涉及训练长度、频率缩放、显存和注意力计算成本。

六、GQA：32 个 Q 头，8 个 K/V 头

机制Q 头K/V 头特点
MHAHH表达能力充分，但 KV Cache 最大
MQAH1KV Cache 最小，但可能损失质量
GQAHG在质量和推理效率之间折中

Llama 3 8B 使用 n_heads=32、n_kv_heads=8，所以每 4 个 Query 头共享一组 Key/Value：

Q: [S, 32, 128]
K: [S, 8, 128] → 按组重复到 32 个头
V: [S, 8, 128] → 按组重复到 32 个头
每个头的 attention score: [S, S]

GQA 不是把 Q 也减少成 8 个头，而是只减少 K/V 的头数。这样可以明显减少自回归生成时缓存的 K/V，同时保留较多 Query 子空间。

显存收益

KV memory ∝ 2 × layers × batch × seq_len × n_kv_heads × head_dim × bytes_per_element

从 MHA 的 32 个 KV 头降到 8 个，相同 dtype、层数、序列长度下，K/V 缓存部分大约降为四分之一。这也是 GQA 对长上下文和大 batch 推理很有价值的原因。

七、Scaled Dot-Product Attention 与 causal mask

Q = XW_Q，K = XW_K，V = XW_V
Attention(Q,K,V) = softmax(QKᵀ / √d_head + mask)V

课程代码先计算 QKᵀ，再除以 sqrt(128)。Decoder-only 模型不能偷看未来 token，因此使用上三角 causal mask，把未来位置的分数设为负无穷，softmax 后对应概率接近 0。

常见 mask 形状包括 [1,1,S,S]、[B,1,S,S]；增量解码时常见 [B,1,1,S]。排查问题时必须确认 mask 能正确广播到 attention scores。

八、SwiGLU：Llama 的 FFN

SwiGLU(x) = W₂( SiLU(W₁x) ⊙ W₃x )

普通 FFN 可以理解为“升维 → 激活 → 降维”。SwiGLU 使用两个投影分支：一个经过 SiLU 产生门控，另一个提供被门控的特征，逐元素相乘后再由 W₂ 投影回 hidden size。

  • W1 和 W3 把 4096 维表示升到 FFN hidden dimension。
  • SiLU(W1x) 提供平滑的门控信号。
  • W2 把结果投影回 4096 维，并通过残差连接加入原表示。

面试时可以强调：Attention 负责 token 间的信息混合，FFN/SwiGLU 负责每个 token 内部的非线性特征变换；两者职责不同。

九、完整 Llama 3 Block 的数据流

h₀ = Embedding(tokens)

每一层：
x = RMSNorm(h)
q, k, v = Linear(x)
q, k = RoPE(q, k)
a = CausalGQA(q, k, v)
h = h + Wo(a) # attention residual

x = RMSNorm(h)
h = h + SwiGLU(x) # FFN residual

final = RMSNorm(h)
logits = final[-1] @ W_outputᵀ
next_token = argmax(logits)

课程 Notebook 把这条链路拆开：先手工算第一层第一个 head，再循环完成多头注意力，再完成 FFN，最后把同样的逻辑放进 32 层循环。它的价值不在于替代工业推理框架，而在于让每个矩阵的形状和作用都可见。

十、KV Cache：推理加速的核心

自回归生成第 t 个 token 时，历史 token 的 K/V 已经计算过，并且不会因为新 token 出现而改变。没有 KV Cache 时，每一步都重新处理完整前缀；有缓存时，只计算新 token 的 Q/K/V，把新的 K/V 追加到缓存中。

Prefill：一次处理 prompt，建立每层 K/V cache
Decode step t：只处理新 token 的 Q/K/V
Q_new 与 [K_history, K_new] 做注意力
将 K_new、V_new 追加回 cache
kv_cache[i]['k']  # [batch, heads, cached_seq_len, head_dim]
kv_cache[i]['v']  # [batch, heads, cached_seq_len, head_dim]

简化版 Notebook 第一次完整输入时建立 cache；之后只取 input_ids[:, -1:]，并把新 K/V 与历史缓存沿序列维拼接。真实 Llama 3 会进一步结合 GQA，让缓存的头数是 8 而不是 32。

对于生成长度为 T 的序列，不使用 Cache 时，每一步都对不断增长的完整序列重复计算，累计代价明显更高；使用 Cache 后，每一步只对一个新 Query 与历史 K 做匹配，单步约为 O(t)。Cache 不会把每一步变成常数时间，但会消除历史 Q/K/V 的重复投影和重复计算。

重要：KV Cache 主要优化推理 decode，不会直接减少模型参数，也不会让训练阶段天然变快。

十三、面试高频问答

Q1：Llama 3 为什么使用 GQA？
因为生成时 K/V 会缓存，KV 头数越多，缓存显存和读写压力越大。Llama 3 8B 使用 32 个 Query 头和 8 个 KV 头，在保留多头 Query 表达能力的同时，把 K/V Cache 规模降到 MHA 的约四分之一。

Q2：GQA 和 MQA 的区别是什么？
MQA 让所有 Query 头共享一组 K/V；GQA 让若干 Query 头分组共享一组 K/V，是 MHA 和 MQA 之间的折中。

Q3：RoPE 为什么同时作用于 Q 和 K？
Attention 分数来自 QKᵀ。对 Q、K 施加与位置有关的旋转后，它们的内积会带上相对位置信息。

Q4：RMSNorm 和 LayerNorm 有什么区别？
LayerNorm 会减均值并除标准差；RMSNorm 不减均值，只按均方根缩放，计算更简单。Llama 3 使用 RMSNorm。

Q5：SwiGLU 比 ReLU FFN 多了什么？
它有两个上投影分支，一个经 SiLU 后作为门控，与另一分支逐元素相乘，再通过下投影。

Q6：KV Cache 缓存的是什么？
缓存每一层历史 token 的 Key 和 Value，不缓存 Query。当前步骤只产生新 token 的 Query。

Q7：KV Cache 能把每一步变成常数时间吗？
不能。新 Query 仍然要和全部历史 K 做匹配，所以单步仍随上下文长度线性增长；Cache 消除的是历史投影和历史 K/V 的重复计算。

Q8：训练时为什么通常不用同样的 KV Cache？
训练阶段整段序列已知，可以通过 causal mask 并行计算所有位置；KV Cache 主要服务于自回归推理。

Q9：如何排查 Transformer 的 shape bug？
固定记录 [B,S,D]、[B,H,S,d]、[B,H,S,S]，重点检查 head 拆分、transpose、mask 广播、GQA 的 KV repeat 和最终 concat。

Q10：8B 指什么？
指模型参数量约 8 billion，不是上下文长度，也不是显存需求。BF16/FP16 下仅权重就大约需要 16 GB。
