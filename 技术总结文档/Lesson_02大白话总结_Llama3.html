二、先把大模型想象成一个“读题和答题的人”

假设模型正在读这句话：

“小明把书放在桌子上，因为它太重了。”

模型需要判断“它”更可能指书，还是指桌子。它不能只看当前这个词，而要回头看前面的词，并判断哪些词和当前问题最相关。

Transformer 的 Attention 就像模型的“快速查资料能力”：

  • 当前词提出问题：我应该关注前面的哪些词？
  • 前面的词告诉模型：我能提供什么信息？
  • 模型给重要信息更高权重，给不重要信息更低权重。

三、Token 是什么？

模型不直接读汉字、英文单词或句子。Tokenizer 会先把文本切成一小段一小段的 token。

人类看到： Transformer 很强
模型看到： 一串数字，例如 [128, 9345, 276, ...]

Token 不一定等于一个字，也不一定等于一个单词。英文中的一个长单词可能被拆成几段，中文也可能按字、词或子词切分。

面试说法： Tokenizer 负责把离散文本映射成 token ID；Embedding 再把 token ID 映射成模型可以计算的连续向量。

四、Embedding：把数字变成“有含义的坐标”

Token ID 只是一个编号。比如 token 123 和 token 456，并不是 456 比 123“更大”或“更重要”。模型需要把它们变成一串向量。

Embedding 可以理解为一张巨大的通讯录：

token ID → 查表 → 这个 token 的向量

向量中的每个数字不是人类直接能读懂的含义，但经过训练后，语义、语法和上下文关系会分布在这些数字中。

五、Attention：每个词都在“问问题、找资料、拿答案”

Attention 中有三个名字很容易让人头晕，可以把它们想成图书馆：

术语大白话作用
Query，Q当前读者的问题我现在想找什么信息？
Key，K每本资料的标签这份资料和我的问题匹不匹配？
Value，V资料的实际内容匹配后，真正拿来使用的内容是什么？

计算过程可以先不要背公式，只记住：

  1. 用 Q 和 K 比较相关性。
  2. 把相关性变成权重。
  3. 按照权重从 V 中取信息。

如果一句话有 10 个 token，模型会形成一个“10×10 的关注关系表”：每个 token 都可以查看其他 token，但 Decoder 模型不能查看未来 token。

六、RoPE：让模型知道“谁在前、谁在后”

Attention 本身只擅长看“哪些词相关”，但不天然知道词语的顺序。

没有位置信息： “猫吃鱼”和“鱼吃猫”可能只被看成同一堆词。
有位置信息： 模型知道谁先出现、谁后出现。

第一课的做法是：把一个位置向量加到 token 向量上。

RoPE 的做法更像是：根据 token 所在的位置，把 Attention 中的 Q 和 K 旋转一个不同角度。

可以把每个 token 想成一根小指南针：

  • 第 1 个位置旋转一个角度；
  • 第 2 个位置旋转另一个角度；
  • 两个 token 的 Q 和 K 做匹配时，旋转角度差会影响匹配结果。

为什么不旋转 V？ 因为 Q 和 K 负责判断“看谁”，V 负责提供“看到了什么”。位置信息主要需要影响前面的匹配过程。

面试说法： RoPE 通过旋转 Q/K 把位置信息注入 Attention，使注意力分数能够自然体现 token 的相对位置关系。

七、GQA：很多人提问，少数资料柜共享

普通多头 Attention 中，每个 Query 头都有自己的一套 K/V。这样表达能力强，但推理时需要缓存很多 K/V。

Llama 3 8B 使用 GQA：

32 个 Query 头
8 个 Key/Value 头
每 4 个 Query 头共享一套 K/V

生活类比：

  • MHA：32 个学生，每个人都有一间资料室。
  • MQA：32 个学生，共用 1 间资料室。
  • GQA：32 个学生分成 8 组，每组共用 1 间资料室。

GQA 的好处是：模型仍然有很多 Query 角度，但需要保存的 K/V 资料少了，生成速度和显存占用更友好。

面试时记住：

GQA 减少的是 K/V 头，不是 Query 头。 Llama 3 8B 的比例是 32 个 Q 头对应 8 个 KV 头。

八、RMSNorm：先把数值音量调到合适大小

神经网络层数很多时，数字可能越来越大或越来越小，训练会不稳定。

Norm 可以理解成“自动调音器”：不改变信息的主要方向，只把数值大小调整到合适范围。

LayerNorm 会做比较完整的标准化：先减平均值，再根据波动范围缩放。

RMSNorm 更简单：主要看这组数字整体有多大，然后进行缩放，不专门减平均值。

名称大白话Llama 3
LayerNorm减平均值，再按波动范围调整课程第一课常见
RMSNorm只根据整体能量调整大小Llama 3 使用

九、SwiGLU：让 FFN 学会“有选择地加工信息”

Attention 负责不同 token 之间交流；FFN 负责每个 token 自己加工信息。

普通 FFN 像一个加工厂：

输入 → 放大维度 → 激活函数 → 压回原维度

SwiGLU 像两个加工通道：

  • 通道 A 判断哪些信息应该被放大；
  • 通道 B 提供具体的信息；
  • 两者相乘，相当于一个门控；
  • 最后再压回原来的 hidden size。

所以可以简单理解为：

Attention 负责“和别人交流”，SwiGLU 负责“自己思考和加工”。

十、KV Cache：把已经查过的资料保存起来

模型生成文字时，是一个 token 一个 token 生成的。

例如生成：

今天 → 天气 → 很 → 不错 → ……

如果每生成一个新 token，都把前面所有 token 重新计算一遍，会非常浪费。

KV Cache 的思路是：

已经计算过的历史 K/V 先存起来。
下一次只计算新 token，再让新 token 查询历史资料。

Prefill 是什么？

Prefill 就是模型第一次读完整个 prompt。

比如用户一次输入 100 个 token，模型可以并行处理这 100 个 token，并把它们的 K/V 存进 Cache。

Decode 是什么？

Decode 就是后面一个一个生成新 token。每次只处理最新的 token，历史 K/V 直接从 Cache 取。

阶段像什么主要特点
Prefill先把整道题读完并做笔记可以并行，影响首 token 延迟
Decode根据笔记逐字写答案自回归，KV Cache 影响生成速度

KV Cache 不是让模型一次生成整段话，而是避免重复阅读已经读过的内容。

十一、为什么上下文越长，模型越慢、越占显存？

因为每个词都可能需要查看其他词。

如果有 100 个 token，关注关系大约是 100×100；如果变成 1000 个 token，就大约是 1000×1000。

序列长度增加一倍，完整 Attention 的关系数量大约增加四倍。

另外，生成时历史 K/V 也会不断累积，所以长上下文会带来：

  • Attention 计算量增加；
  • KV Cache 变大；
  • 显存读写变多；
  • 同一张 GPU 能同时服务的请求变少；
  • 长文本位置编码和模型能力可能出现外推问题。

十二、三个推理优化技术，用大白话区分

技术大白话解决什么问题
GQA让更多人共享资料柜减少 KV Cache 的体积
FlashAttention分批处理资料，不把整张大表摊在桌上减少 Attention 中间结果的显存读写
量化用更少的位数保存数字减少模型权重和 Cache 的内存
PagedAttention把显存切成可灵活分配的小格子减少碎片，提高多请求服务效率

它们不是互相替代的关系，而是可以一起使用：

GQA 减少缓存数量，量化减少每个数字的大小，PagedAttention 管理缓存位置，FlashAttention 优化注意力计算过程。

十四、面试时的最简回答

问：Llama 3 做了什么优化？
答：Llama 3 仍然是 Decoder-only Transformer，但使用 RMSNorm、SwiGLU、RoPE 和 GQA。RoPE 负责位置信息，GQA 减少 K/V 头从而降低 KV Cache，RMSNorm 稳定数值，SwiGLU 增强 FFN 的非线性表达。

问：KV Cache 是什么？
答：生成每个新 token 时，历史 token 的 K/V 不会改变，因此把它们缓存起来。Prefill 负责处理完整 prompt，Decode 阶段只计算新 token，并复用历史 K/V。

问：长上下文为什么慢？
答：Attention 要建立 token 两两之间的关系，关系数量随序列长度平方增长；生成阶段 KV Cache 又会随上下文线性变大，因此计算、显存和带宽压力都会上升。

十五、现在只需要先记住这 8 句话

  1. Attention：当前 token 去查找相关的历史 token。
  2. Q：我想找什么；K：我有什么标签；V：我实际提供什么内容。
  3. RoPE：通过旋转 Q/K，让模型感知位置和相对距离。
  4. GQA：32 个 Query 头共享 8 个 K/V 头，减少缓存。
  5. RMSNorm：把数值大小调稳定，Llama 3 不使用普通 LayerNorm。
  6. SwiGLU：两个 FFN 分支，一个负责门控，一个负责提供信息。
  7. Prefill：读完整个 prompt 并建立缓存；Decode：利用缓存逐个生成。
  8. FlashAttention、量化、PagedAttention 分别优化计算 IO、数字精度和缓存管理。

建议学习顺序：先把这份大白话总结读顺，再回到正式版总结看 shape 和公式；最后打开 Notebook 对照代码。不要一开始就试图把所有公式一次性背下来。
