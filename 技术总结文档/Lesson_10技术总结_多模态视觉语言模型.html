1. 一句话：这一课解决什么问题？

理解模型怎样把图片变成可处理的视觉特征，再与文本一起输入语言模型，并通过本地看图问答和小规模训练连接理论与代码。

大白话

前几课的模型主要读取文字；多模态模型还要接收图片等不同类型的信息。语言模型不能直接把 JPEG 文件当作普通文字理解，所以系统先将图像处理为数字张量，再让视觉编码器提取特征，随后把特征转换或融合到语言模型可以使用的表示中。

你可以把视觉编码器看作“看图并提取线索的部分”，投影或融合模块看作“把视觉线索整理成语言模型能接收的形式”，语言模型负责结合问题和视觉信息生成文字。但这个比喻不意味着每个多模态模型都只有一个线性投影层；不同架构的融合方式可能不同。

与 Lesson 7、8 的连接：结构仍包含模型、数据、loss 和参数更新。新增的是图片预处理、视觉编码、图文对齐和融合，以及图像相关的显存与计算成本。

3. CNN、ViT、CLIP：先建立直觉

概念它解决什么问题关键理解
CNN / 卷积从图像中逐层提取局部特征。卷积核在局部区域滑动；低层可学到边缘等特征，更深层组合更复杂的模式。
ViT把图像组织成 patch 序列，交给 Transformer 处理。例如 224×224 图像、16×16 patch，可得到 14×14=196 个图像 patch；通常还需要位置表示。
CLIP学习图像与文字之间的对应关系。图像编码器和文本编码器把图文映射到可比较的空间，用图文对进行对比学习。CLIP 本身的图文相似度训练不等于能直接完成任意多轮看图对话。

在 MiniVLM 中使用的是课程包提供的 CLIP 图像编码器；它输出的视觉特征再经过项目的投影层送入小语言模型。Qwen2.5-VL 是另一种更复杂的实现，不能把 MiniVLM 的具体结构和尺寸直接套过去。

4. MiniVLM：一张图如何进入语言模型？

对应源码：model_vlm.py 和 dataset.py。

图像 → CLIP 图像预处理 → 224×224 张量
    → ViT 图像特征：196 个 patch，每个 768 维
    → VisionProj：768 维映射到 512 维
    → 替换文本中对应的 196 个图像占位 token 的 embedding
    → 语言模型 Transformer → logits → 回答 token 的 loss

本次实际检查到的输入

对象本次 shape / 数量说明
X、Y、loss_mask[639] / 样本最大序列长度设 640，输入和标签错开一位，实际有效监督 token 为 14。
图片张量[1, 1, 3, 224, 224] / 样本单样本包含一张图，内部保留的额外单例维度在 forward 中处理；DataLoader 再增加 batch 维度。
图像占位位置196 个连续占位 token本次确认其 ID 序列与代码预设匹配，才能将图像特征替换到对应位置。
视觉特征及投影[196, 768] → [196, 512]来自代码结构：去掉 CLIP 特殊位置后使用 patch 特征，线性层将维度映射到语言模型维度。
为什么要投影？因为视觉编码器输出维度和语言模型的隐藏维度不同；投影层使形状能够对接，并需要通过训练让表示更适合语言模型使用。维度一致只是必要的接口条件，不代表语义已经对齐。

5. Qwen2.5-VL：真实看图问答

本机已有 Qwen2.5-VL-7B-Instruct，课程示例原本指向 3B。我们适配了 predict_qwen2_5_vl.py，读取本地模型和课程图片 294574.jpg，询问图片中的主要物体和场景。

实际结果：模型回答主要是彩色风筝、开阔场地，以及远处建筑和树木；与图片主要内容基本一致。它还推测可能是海滩等细节，不能把推测当成已证实的视觉事实。
处理后的字段本次实测含义
input_ids[1, 333]batch 1；总共 333 个输入 token，其中 299 个为图像 token。
pixel_values[1196, 1176]本模型预处理后展平的 patch 表示；不是普通的 [B,3,H,W] 图片 batch。
image_grid_thw[[1, 26, 46]]处理后视觉网格的时间、高、宽；26×46=1196 个 patch。模型配置的空间合并尺寸为 2，因此本例合并后为 1196÷4=299 个视觉 token。

这些数字只适用于这张图片、本次像素限制和这份模型配置。图片尺寸、处理器参数和模型版本改变时，数量会变化。

6. MiniVLM 单步训练：运行与排查

已运行：在 RTX 3090 上使用课程预训练语料中的 1 条图文样本，运行 1 次前向、loss、反向和优化器步骤；修复精度配置后 loss 为 6.588，可训练参数约 3.213M。通过对比相同初始化种子下的权重，确认投影层参数实际发生变化。

原训练代码冻结视觉编码器等参数，并额外解冻 model.layers[-1:]，即最后一层语言模型层；因此本次可训练参数不只包含投影层。单步更新只证明训练链路有信号，不能证明图文对齐效果或问答能力提升。

现象原因 → 定位 → 修复 → 验证
第一次运行有 loss，但投影层权重没有变化脚本的 dtype 默认写 BF16，但 CUDA autocast 没有按该参数指定精度；使用 FP16 梯度缩放时，对比发现投影参数未变化，推测梯度溢出导致更新被跳过；当时未直接记录缩放器状态或非有限梯度，因此原因尚未完全证实。
修正自动混合精度在 train_pretrain_vlm.py 中将 dtype 显式传给 autocast，并只在 CUDA FP16 下启用 GradScaler；重跑后投影权重平均绝对变化约 0.000440。该数值只是一次更新的检查，不是模型质量指标。
完整数据量较大课程预训练数据约 59.5 万条、SFT 数据约 15.9 万条；本次只取 1 条。输出位于临时目录，不覆盖课程原权重，临时目录可能被系统清理。

学习用小实验不等于完整多模态预训练、完整 SFT 或模型效果评测。对生成结果还需要独立样本、事实一致性、细粒度识别和业务指标等检查。

8. 设计收益、代价和常见失败

设计收益代价或限制
视觉编码器 + 语言模型复用视觉理解和语言生成能力。不同模块的特征空间需要对齐；视觉细节可能丢失。
冻结部分模型，只训练投影层或少数层减少训练参数及资源需求。可适应能力受限；实际冻结哪些层要以代码为准。
增加图片分辨率通常保留更多细节，对小字和小物体可能有帮助。视觉 token、显存和延迟通常增加；具体增长取决于 patch 与压缩策略。
图文 SFT / LoRA可利用任务数据调整回答方式或领域能力。质量受数据与标签影响；仅少数训练步不能证明泛化；数据还可能存在错误或版权问题。

排查看图问答应依次检查：图片路径与解码 → processor 和模型版本 → 图像 token 和视觉特征匹配 → 显存、输入长度 → 输出结果是否有证据。常见失败包括图片未真正进入模型、图像分辨率不足、张量设备不一致、占位符与特征数量不匹配，以及模型对细节产生幻觉。

追问速答

  • 为什么语言模型能“看图”？它不是直接读 JPEG，而是通过视觉编码和融合，把图像信息变成模型内部可使用的特征表示。
  • 投影层解决什么？连接视觉特征与语言模型隐藏维度，并在训练中学习更合适的映射；维度匹配本身不保证语义对齐。
  • CLIP 和多模态对话模型有什么不同？CLIP 主要学习图文匹配表示；对话模型还要结合视觉信息与指令生成文本。
  • 图片越大为什么更慢？更多 patch 或视觉 token 通常带来更多视觉编码和后续序列计算；具体受模型的压缩与处理策略影响。
  • loss 有值就证明训练成功吗？不一定。还要确认梯度有限、优化器真正执行、目标参数确实变化；本次就发现了被跳过的更新。
  • 你亲自验证了什么？一次 Qwen 看图问答和 MiniVLM 一步参数更新；完整微调与独立效果评测没有完成。
