1. 一句话：这一课解决什么问题？

学习怎样利用奖励或偏好信号调整大模型行为，并通过一个电影评论续写实验观察 PPO 的生成、评分与参数更新过程。

大白话：接上 Lesson 8

Lesson 8 的 SFT 给模型示范“这种问题可以这样回答”。但真实任务中，同一个问题往往有多种可能答案，我们还希望模型更倾向于有帮助、更符合偏好或满足规则的答案。Lesson 9 就是在学习怎样把这种偏好或目标转成训练信号。

RLHF 可以理解为“用人类反馈帮助模型对齐”：常见流程是收集人对回答的偏好，训练奖励模型，再利用奖励调整模型。这次跑的示例比较特殊：它直接用现成的情感分类器打分，鼓励正面影评；我们没有自己收集人类反馈或训练奖励模型。

目标要定义清楚：奖励高代表更符合所设计的评分规则，不自动代表真实、全面或有用。比如一个只追求正面情绪的模型，可能写出不符合原评论观点的续写。

2. 本课实际实验：一条 PPO 链路

IMDB 影评 → 截取开头，组成 prompt
     → 策略模型 Qwen2.5-0.5B 生成续写
     → 情感分类器为 prompt + 续写打正面情绪分
     → PPOTrainer 结合参考策略与价值估计计算更新
     → 更新策略模型和价值头

本次从课程包的本地数据集中抽取 4 条影评，每条最多生成 24 个新 token；完成了 1 次 PPO 更新。策略模型、参考模型及情感分类模型均来自课程包，本次没有请求云端模型 API。

与 Lesson 8 的区别

环节输入与训练信号直觉
SFT用户输入 + 示范回答；交叉熵监督示范答案。“照这个回答方式学。”
本次 PPO模型自己生成续写；情感分类器给分，再用于策略优化。“先自己写，得分再影响更新。”
DPO一个问题 + 较好回答 + 较差回答；基于偏好对计算目标。“同一道题，比较哪份答案更受偏好。”

3. PPO 中的四个角色

角色大白话本实验中的对应物
策略模型 Policy负责写答案，是我们希望改进的模型。AutoModelForCausalLMWithValueHead 包装的 Qwen2.5-0.5B-Instruct。
参考模型 Reference提供一个固定的参照，衡量当前策略与原策略的偏离。另一个加载同一模型的实例，参数冻结；不是负责生成最终答案的模型。
奖励模型 Reward按规则给回答打分；在不同项目中可由人类偏好训练，也可由规则或外部模型提供。现成 DistilBERT 情感分类器；提取 POSITIVE 分数。
价值头 Value Head估计当前位置往后可能获得的回报，帮助计算优势。TRL 策略模型包装器中的价值头；不是额外运行的情感分类器。

这些是功能角色，不意味着必须始终加载四个完全独立的大模型；具体参数共享、部署方式依赖实现。

4. PPO 的关键直觉与最少公式

奖励、价值和优势

奖励是评分器给出的反馈；价值估计是模型对未来回报的预测。优势 A可以直观理解为“结果比当前预期好多少”：大于零时，更新倾向于提高相关动作的概率；小于零时，倾向于降低。具体优势由实现结合奖励、价值估计等计算，不能简单等同于原始情感分数。

限制更新幅度

概率比率 r = 当前策略产生该 token 的概率 / 采样时旧策略产生该 token 的概率
裁剪目标（示意）= min(r × A, clip(r, 1−ε, 1+ε) × A)

r 是概率比率；A 是优势；ε 控制裁剪区间；clip 把比率限制在指定范围。直觉是：模型朝有利方向调整，但不要让一次更新过于激进。对于负优势，裁剪效果的方向也要按公式判断，不要机械地说“所有比率都被强制限制”。

参考模型的 KL 惩罚与 PPO 裁剪是两件事：前者衡量策略相对参考策略的偏离并形成惩罚，后者针对当前策略与采样旧策略之间的比率控制更新；它们各有作用。

关键数据形状

语言模型输入通常是 token ID，填充后形状为 [B, T]；生成文本各自长度可能不同。每条生成通常有一个序列级原始奖励；实现还需将训练相关的 log probability、mask、优势和价值与 token 位置对齐。代码中生成与优化细节由 TRL 封装，不应凭调用入口断言所有内部 tensor 的具体维度。

5. GRPO、DPO 与 PPO 怎么区分？

方法训练信号和做法收益与限制
PPO采样回答，结合奖励、价值估计、旧策略和参考策略优化。反馈灵活，但采样与训练链路较复杂，涉及多个模型角色和超参数。
GRPO每个问题采样一组回答，基于组内奖励计算相对优势；具体归一化与损失随实现而异。常见做法无需单独价值模型，但一组多次生成需要时间和显存；若组内分数没有差异，学习信号可能很弱。
DPO对静态偏好对比较当前模型和参考模型对优选/劣选回答的相对 log 概率，直接优化偏好目标。不需要单独训练奖励模型或在线运行 PPO；依赖偏好数据的质量、覆盖范围和正确实现。

这里的“优选/劣选”来自数据标注或构造规则，不代表回答绝对正确。DPO 往往使用离线数据；PPO 和 GRPO 通常围绕当前策略采样，具体是否 on-policy 需结合实现和采样策略判断。

8. 失败场景、排查与代码限制

现象原因 → 定位 → 处理 → 验证
第一次启动时导入报 NumPy 属性错误独立环境中的 NumPy 1.26 与继承到的较新 SciPy 版本不兼容；在独立环境安装兼容的 SciPy 1.14.1 和 pandas 2.2.3 后，PPO 实验完成。
原 PPO 配置规模较大原脚本配置 batch size 128 和较长生成，还会保存权重；在临时副本中缩小为 batch 4、生成上限 24、1 次更新，不覆盖课程权重。
DPO 代码不能只看 loss 是否输出静态阅读发现 get_log_prob 直接用同位置 logits 对 labels 取概率，未按因果语言模型的下一 token 预测进行错位；回答掩码也可能把 padding 计入。应修正并用小样本验证后再训练；上述问题已修正，后续训练与评估结果见顶部验证更新。

工程上的后续问题

  • 奖励模型可能被“钻空子”：高分不等于符合用户意图，需要检查奖励定义、生成样本与独立评测。
  • 策略更新过大可能损伤已有能力；需要监控参考策略偏离、训练稳定性和任务表现，不能只盯奖励。
  • 长输出、多个模型和采样次数会影响显存和吞吐；优化前先测量实际瓶颈。
  • 课程示例把 prompt 与续写一起送进情感分类器；模型看到的不只生成内容，实际评分语义要结合输入格式分析。

9. 面试回答

30 秒版本

我学习了 PPO、GRPO 和 DPO 的对齐思路，并运行过一个小型 PPO 实验。它让 Qwen 续写影评，用情感分类器给正面情绪打分，再由 PPOTrainer 更新策略。实际只跑了 4 条样本、1 次更新，验证了生成、评分与训练链路；没有完成长期训练，也没有训练人类反馈奖励模型；另外用 256 条独立测试样本对课程权重做过情绪评分对比。

2 分钟版本

SFT 是基于示范答案进行监督训练；对齐训练进一步利用奖励或偏好，调整模型生成倾向。PPO 中，策略模型生成输出，奖励模型提供分数，价值头辅助估计优势，冻结参考模型用于偏离约束，PPO 的比率裁剪用于控制相对旧策略的更新。

我运行了课程的影评续写示例，用 0.5B Qwen、情感分类器和本地 IMDB 数据，缩小到 4 条样本、1 次 PPO 更新。为避免影响其他课程，我使用了独立环境和临时脚本。实验只验证技术链路，没有保存权重或证明效果提升。阅读 DPO 示例时还发现概率位置对齐和 padding 掩码的问题，已修正并完成 100 次更新和独立样本验证；直接偏好正确率未见提升。

面试官追问

  • 为什么 SFT 后还需要对齐？示范数据不一定覆盖所有回答质量比较；奖励或偏好数据可补充目标，但不能保证没有副作用。
  • 参考模型有什么用？作为固定基准，相关 KL 惩罚可帮助限制策略远离参照；它和 PPO 的概率比率裁剪不是同一个机制。
  • GRPO 为什么能减少价值模型？常见 GRPO 利用同一问题的一组回答的相对奖励估计优势；代价是多次采样和对奖励差异的依赖。
  • DPO 还需要奖励模型吗？标准 DPO 的训练目标直接利用偏好对和参考模型，一般不需要单独训练奖励模型或在线 PPO；偏好数据仍需可靠来源。
  • 高奖励就意味着好模型吗？不是，奖励只衡量评分规则；还要检查任务质量、泛化、事实性、奖励漏洞和独立评测。
  • 你亲自做了什么？明确说跑通了 1 次 PPO 更新，其他算法和效果评估尚未完成。
