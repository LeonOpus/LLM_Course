1. 一句话：这一课解决什么问题？

通过训练一个小型因果语言模型 NanoQwen，理解模型怎样从文本中学习预测下一个 token，以及训练数据、模型、loss 和参数更新如何连接起来。

大白话

Lesson 5、6 是把已经有能力的模型接入知识库、搜索和 Agent。Lesson 7 往前走：模型最初怎样从大量文本中形成语言能力？

预训练可以理解为大量做“文本接龙练习”：把前面的 token 给模型，让它猜下一个；拿正确答案比较，计算猜得有多偏，再调整模型参数。重复很多次之后，模型有机会学到语言、知识及一些模式。它学到的能力并不等于可以保证事实正确，也不天然等同于会遵循用户指令。

Lesson 1、2 已学 Transformer、RoPE、GQA 等模块：本课是在这些计算模块之上加入数据、损失函数、反向传播与优化器，理解参数怎样被训练出来。

课程代码是教学性质的小模型和小规模语料。工业级大模型预训练还涉及海量数据治理、分布式训练、容错、评测等工程；本次没有完成这些工业流程。

2. 整体流程：一次训练经过哪里？

JSONL 文本 → tokenizer 分词、补齐或截断 → 构造错位的 X、Y 和 loss_mask
           → DataLoader 组成 batch → NanoQwen 前向传播 → logits
           → 交叉熵 loss（忽略 padding 标签）→ 反向传播求梯度
           → 梯度裁剪 / AdamW 更新参数 → 按间隔保存权重

一次模型调用可以同时计算序列中多个位置的预测。因果注意力保证位置只能利用自己和更早的 token；训练时各位置的输入来自真实文本，通常称为 teacher forcing。生成时则从已有前缀逐个生成，再把生成结果用于后续步骤。

“预训练”是模型参数学习阶段；“推理”是使用已有参数生成输出。项目的训练脚本默认从新建模型开始；评估脚本则加载已保存的模型权重。

3. 数据：文本怎样变成训练题？

第一步：读取 JSONL

lm_dataset.py 的 PretrainDataset 逐行读取 JSON，每行预期有 text 字段。课程目录里约有 1.6 GB 的语料文件。本次只取了其中 8 条进行训练链路验证。

第二步：tokenizer 把文本映射为整数

token 可以理解为分词器词表中的片段，它不一定对应一个字或一个完整单词。实际使用项目自带 tokenizer，关闭自动添加特殊 token 时，今天天气很好 编码为 [4668, 3858, 5675]，词表大小为 6400。数字只是词表中的编号，不是词语的大小或重要程度。

第三步：输入和答案错开一位

以下使用容易看懂的示意 token，不是上面那句话的真实编码：

原始 token：  [A, B, C, D, PAD]
输入 X：       [A, B, C, D]
目标 Y：       [B, C, D, PAD]
loss_mask：    [1, 1, 1, 0]

位置 0 输入 A，目标是 B；位置 1 可看见 A、B，目标是 C；后面的 padding 只是凑长度，不应当成为需要学习的答案。代码使用 input_ids[:-1] 和 input_ids[1:] 构造 X、Y，掩码也相应右移。

长度细节：代码把每条文本补齐或截断到 max_length，然后左右各去掉一个 token。因此默认 512 得到的是长度 511 的 X、Y；本次实验设置 128，得到长度 127。对于较长文本，超出上限的部分会被截断。

4. 模型和 shape：数据进来后发生什么？

本次实验使用默认的模型宽度 512、8 层、8 个注意力头、2 个 KV 头和 6400 词表；batch size 为 2，分词长度设为 128。

位置本次实验的 shape含义
输入 X、标签 Y、mask[2, 127]2 条样本，每条有 127 个预测位置。
Embedding 后 / Transformer 隐藏状态[2, 127, 512]每个 token 用 512 维向量表示。
输出 logits[2, 127, 6400]每个位置对词表中 6400 个候选 token 给出分数。
loss标量对有效目标位置的交叉熵求平均后得到一个数。

通用地说，batch 为 B、预测长度为 T、隐藏维度为 H、词表大小为 V 时：X/Y [B,T] → 隐藏状态 [B,T,H] → logits [B,T,V]。logits 是未归一化分数，不直接等于概率。

回扣 Lesson 1、2

  • 单个注意力头维度为 512 ÷ 8 = 64；2 个 KV 头配 8 个 Q 头，属于 GQA 结构。
  • 模型使用 RoPE 和 RMSNorm；有可选 MoE 代码，但本次默认没有启用 MoE。
  • 输出层和 token embedding 的权重在代码中共享；这能减少独立参数量。
  • 代码尝试调用 PyTorch 的 scaled dot product attention；具体使用哪种底层 kernel 取决于运行环境，不能仅凭开关断言一定是某一种 FlashAttention 实现。

5. loss、梯度和参数更新

先说直觉

模型在每个位置给所有候选 token 打分。交叉熵衡量它对正确答案分配的概率是否足够高：正确答案概率越高，该位置损失通常越低。多个有效位置的损失再求平均，得到本批次的训练信号。

有效位置的平均 loss = Σ（每个位置交叉熵 × mask）÷ Σ mask

其中 Σ 表示对 batch 和位置求和；mask 为 1 表示计入，为 0 表示忽略。代码还会加上模型返回的辅助损失；使用 MoE 时可能用于负载均衡。

代码中的顺序

  1. 前向传播：res = model(X) 得到 logits。
  2. 计算每个位置的交叉熵，乘 loss_mask，再对有效位置求平均。
  3. backward() 计算各参数的梯度。梯度可以理解为 loss 对参数变化的敏感方向。
  4. 累计到指定步数后，裁剪梯度，再由 AdamW 根据梯度和学习率更新参数。
  5. 清空梯度，继续下一个 batch；按间隔保存模型权重。
学习率决定单次更新的尺度；梯度累积让多个小 batch 共同贡献一次更新，可以在显存有限时近似使用更大的有效 batch。近似有效 batch = 单卡 batch × 累积步数 × 数据并行进程数；具体还受最后一个不完整 batch 等因素影响。

loss 下降如何理解？同一批数据、设置一致时，loss 下降通常意味着模型更会预测这些目标；但训练批次不同或只看几步时，不能仅靠数字判断泛化能力。还应看独立验证集、生成质量和具体评测。

8. 设计收益、代价与代码限制

设计收益与代价
固定长度 + padding容易组成 batch；短样本的填充会浪费计算，长样本会被截断。mask 避免把 padding 目标计入 loss。
GQA多个 Q 头共享较少的 KV 头，有助于减少 KV 表示和推理缓存；效果与具体模型和实现相关。
梯度累积与混合精度有助于在有限显存下训练，但要关注数值稳定、正确的精度设置和实际更新次数。
保存模型权重可用于加载推理；当前保存的是权重，没有同时保存优化器、调度器和完整训练状态，因此不等于完整可恢复训练检查点。

从代码观察到的限制

  • 学习率：get_lr 实际写法为 lr/10 + 0.5*lr*(1+cos(...))，起始是 1.1 倍基础学习率；日志首步 0.00055 对应基础值 0.0005。代码中的 warmup_iters 参数未见用于调度。
  • 混合精度：--dtype 用于控制 GradScaler，但 CUDA autocast 未传 dtype；不能仅因默认参数写着 bfloat16 就断定实际前向使用 BF16。
  • 梯度累积：只在累计步数整除时更新；如果一个 epoch 的 batch 数不是累积步数的倍数，尾部梯度没有在 epoch 末单独提交。当前训练结束时也没有专门处理剩余梯度。
  • 数据与保存：数据集把 JSONL 全量读入内存；非分布式加载时 shuffle=False；只按保存间隔写权重，未到间隔结束时不保证有最终权重。大规模场景需要重新设计。

以上是代码阅读发现，不表示本次已完整测试所有边界条件。预训练数据还需要关注质量、去重、隐私、版权、混合比例和验证集污染；本次没有实际完成这些数据治理环节。

9. 面试版回答

30 秒

我学习并运行了一个小型因果语言模型 NanoQwen 的预训练流程。数据经过 tokenizer 后构造错位的输入和标签，模型预测下一个 token，用交叉熵和 padding 掩码计算 loss，再通过反向传播和 AdamW 更新参数。我实际用 8 条数据在 GPU 上跑通了 4 步训练，也单独加载课程自带权重做了续写；没有完成完整预训练。

2 分钟

这节课承接 Transformer 结构，主要解决模型参数如何从文本中学出来。项目读取 JSONL 文本，用自带 tokenizer 编成 token ID，补齐或截断后把序列错开一位得到 X 和 Y。NanoQwen 通过 embedding、多个 Transformer block 和输出层产生每个位置的词表 logits，训练脚本对有效标签算交叉熵，再反向传播、裁剪梯度并使用 AdamW 更新参数。模型默认使用 8 个注意力头和 2 个 KV 头，体现 GQA，也有 RoPE 和 RMSNorm。

我在 3090 上用 8 条数据跑通了 4 步，验证训练链路；另外加载项目已有权重生成了一段文本。代码阅读中还发现学习率公式起点为基础学习率的 1.1 倍、混合精度参数没有完整映射到 autocast，以及梯度累积尾部处理等限制。由于没有跑完整语料或独立评测，我不会把这个实验表述为训练出了可用大模型。

面试官追问

  • 为什么输入和标签要错开？让每个位置根据已有上下文预测下一 token，充分利用一条序列中的多个预测位置。
  • 训练时为什么可以并行，生成时通常逐个输出？训练已知整段真实文本，可用因果 mask 并行计算多个位置；生成时下一个输入依赖刚生成的 token。
  • padding 为什么不算 loss？它是为凑长度加入的填充，不是我们希望模型学习预测的有效目标；代码对目标位置乘 mask。
  • 预训练、SFT、RAG 有什么关系？预训练主要学习文本分布；SFT 用监督样例继续调整行为；RAG 在推理时检索外部材料辅助回答。它们处在不同环节，可以组合。
  • 梯度累积和直接增大 batch 完全一样吗？理想条件下梯度平均可近似，但随机性、优化器更新频率、学习率调度及不完整 batch 等会带来差异。
  • loss 降了是否证明模型有用？不能单独证明。需要独立验证集、任务评测、生成质量与实际使用约束一起判断。
