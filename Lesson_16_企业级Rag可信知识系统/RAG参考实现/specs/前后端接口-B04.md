# 前后端接口：当前可运行基线

B04 是教师内部开发批次，**不等同于课程 M04 检查点**。课程 M00～M15 见路线表。

## 已实现接口

| 方法 | 路径 | 输入/输出 | 错误 |
|---|---|---|---|
| GET | /api/health | 后端状态、配置存在性、模型名、文件扩展名 | 不把配置存在当成云服务可用 |
| GET | /api/services/milvus | 实际检查本机 Milvus 可达性 | 503 |
| POST | /api/documents | multipart file → 文档元数据，201 | 空文件 400；超过 50 MB 413；类型不支持 415 |
| GET | /api/documents | 已上传文档及解析/入库状态 | 无文档返回空列表 |
| POST | /api/documents/{id}/process | 显式触发真实解析与入库，202 | 未找到 404；处理中或已就绪 409 |
| GET | /api/documents/{id}/blocks | 原始解析规范化后的块 | 未解析 409；未找到 404 |
| GET | /api/documents/{id}/source | 下载原始文件 | 未找到 404 |
| POST | /api/ask | question、strategy、top_k、final_k、可选 doc_ids | 输入无效 422；云服务 502；检索异常 503 |

当前 strategy 为 baseline（dense 召回）或 rerank（dense 后重排）。其他优化尚未接入，不能把“保留表格结构”函数已写好当成前端实验已跑完。

基线每个原始块内使用 600 字符窗口、100 字符重叠，不跨来源块合并。使用字符数而非 token 数，后续要记录上下文预算并对复杂表格做有针对性的优化。

## 状态与恢复

uploaded → parsing → parsed → indexing → ready。只有 ready 文档进入在线检索。处理失败保留错误及原文件；解析结果、云任务 ID、Embedding 缓存存放 runtime。DocMind 提交不确定时不自动重提；人工核对控制台后恢复。

当前使用单后端进程和本机 SQLite 元数据，支持进程内互斥。进程重启后可点“恢复检查”继续 parsing/indexing；运行中的任务会拒绝重复触发。已用 CSV 固定场景验证恢复入口；DocMind 真实任务中断恢复尚待云调用验证，不宣称任务队列具有生产级恢复能力。

## 回答与证据

回答 JSON 含 answered/refused/clarify、正文、引用列表、模型 usage、阶段时间和 trace。无就绪文档时明确拒答、不调用模型。引用 ID 必须存在于本次上下文中，answered 必须有引用；这一检查不等于引用语义正确，仍需评估。

模型生成的图表描述使用 text_origin=docmind_llm 标识；不把它伪装为原始 OCR 文本。DOCX/XLSX 等定位不足时显示块标识，不编造 PDF 页码。
