# 第五章：RAG 从零实操——确认规格 v2

更新时间：2026-09-15。

本文件是需求与编写验收规格，不代表课程、文档语料、200 条评估题或真实实验已经全部制作完成。

## 1. 已确认的定位

- 学员已接触前四章理论，但可能不会 Python、JSON、终端和环境配置。
- Windows 11 为主线，macOS 提供逐步对照；不混用 PowerShell、CMD、zsh 命令。
- 场景：虚构设备产品与售后知识库。所有型号、参数、保修条款均为教学虚构数据。
- 学生通过 Codex 等 AI 编程助手逐步建立 React 前端与 FastAPI 后端。
- 离线入库以 DocMind 为解析主线，在线检索用 Milvus；应用中的生成、Embedding、重排、视觉理解及模型辅助评估使用百炼。
- SDD 指规格驱动开发；TDD 指先写有效失败测试，再实现、通过测试、重构。
- 质量目标：面向复杂企业文档的可追溯检索与回答。保留运行必需的配置、测试、错误处理，不扩展为高并发、集群、多租户与生产运维课程。
- 接受四项辅助设计：阶段恢复点、环境自检、云接口固定样例、必修与选修分层。

## 2. 课前 Python 入门：明确可跳过

章节位置：全章开头，名称“5.0 零基础准备：读懂 AI 写的 Python（了解 Python 可跳过）”。

不要求先完成一整套编程课程；目标是能读懂项目中的数据、配置、函数和错误。

| 单元 | 学习内容 | 对应 RAG 场景 | 验收 |
|---|---|---|---|
| 运行第一份文件 | 文件、目录、扩展名、编辑器、终端、保存后运行 | 创建 hello_rag.py | 学员能重复运行并修改输出 |
| 值与变量 | 字符串、整数、小数、布尔值、None、type | 文件名、页码、相似度、入库状态 | 区分字符串 "3" 和数字 3 |
| 列表 | 有序集合、索引从 0 开始、len、遍历 | 多份文档与多个检索片段 | 取出第一个片段，统计数量 |
| 字典 | 键值对、方括号取值、get、嵌套 | 文档 ID、来源、页码、正文 | 从嵌套结构读出证据来源 |
| JSON | 文本交换格式；object/array 与 dict/list 的对应 | API 请求与响应 | 能区别 Python 字典和 JSON 字符串 |
| 条件与循环 | if、for、缩进、过滤 | 筛选高于阈值的候选片段 | 理解缩进如何改变执行范围 |
| 函数 | 参数、返回值、调用、import | 检索函数返回列表 | 能说明输入和输出 |
| 文件与配置 | UTF-8、相对路径、工作目录、环境变量、.env | 读取配置和文档 | 不把密钥写进前端或聊天记录 |
| 错误与测试 | 最后一行错误、文件与行号、assert、测试结果 | KeyError、路径错误、接口超时 | 提供脱敏错误给 AI 并验证修复 |

必须包含以下容易混淆的对照：

```python
# Python 字典：程序已经可以直接操作的数据。
document = {"name": "设备手册.pdf", "pages": 12, "ready": True}

# JSON 字符串：一段遵循 JSON 规则的文本。
raw = '{"name": "设备手册.pdf", "pages": 12, "ready": true}'

import json
parsed = json.loads(raw)  # JSON 文本 -> Python 对象
assert parsed["pages"] == 12
```

明确 Python 的 True/False/None 对应 JSON 的 true/false/null；JSON 使用双引号、没有注释、不能保留末尾多余逗号。先用小例子理解，再引入项目中的实际 JSON。

跳过标准：能读懂列表内嵌字典、读取 JSON 字段、说明函数输入输出，并独立运行一个文件。提供 5 题自测；自测不通过则回到对应单元。

## 3. 多类型文档接入

常用格式主线：PDF、DOCX、XLSX、PPTX、PNG/JPG、HTML、Markdown、TXT、CSV。

扩展兼容样例：DOC、XLS、PPT、RTF、EPUB；按实际接口与样例验证决定验收状态。音视频不纳入本章必修范围。

DocMind 官方文档当前列出多种 Office、图片、网页及文本格式，但“服务声称支持”与“本项目完成端到端验证”必须分别记录。CSV 走明确的结构化适配路径，不假设 DocMind 原生支持所有扩展名。

| 类型 | 入库处理要求 | 来源定位要求 |
|---|---|---|
| PDF/扫描 PDF | DocMind 解析，保存原始结果、版面块、图表与页信息 | 文档版本＋页码＋可用时的坐标 |
| DOCX | DocMind 主解析，保留标题层级、段落与表格关系 | 标题路径＋段落/表格标识；不伪造固定页码 |
| XLSX | DocMind 主解析；必要时用结构化读取校验表头、单位、工作表和缓存值 | 工作表＋行列/单元格范围，可靠定位不了就降低定位精度并说明 |
| PPTX | DocMind 解析图文与阅读顺序 | 幻灯片序号＋形状/区域标识 |
| PNG/JPG | DocMind OCR/版面理解；必要时用百炼视觉模型辅助，保留来源区分 | 图片文件＋区域坐标 |
| HTML/MD/TXT | DocMind 接入样例，保留原始源文件；结构化适配可作为对照实验 | 标题路径、稳定块标识或行范围 |
| CSV | 原生结构化适配，保留原始行列和编码信息 | 文件＋行列/记录键 |

统一 Document/Block/SourceLocator 结构，但保留各格式的原始定位语义。用户上传入口、错误消息、预览、引用和评估必须一起适配，不能只改上传控件的 accept 属性。

对于表格：数值、单位、表头、合并单元格含义和脚注是一组证据。公式单元格缺少缓存值时明确报出缺失，不臆造计算结果。

## 4. 语料规模与内容质量

编写目标：36 份内容独立的业务文档；另提供至少 6 个同内容不同格式或退化版本，专门用于解析对照，不计入独立文档数。

| 文档形式 | 独立文档数 | 内容职责 |
|---|---:|---|
| PDF | 16 | 产品、安装、维护、保修、故障处理、技术公告等完整资料 |
| DOCX | 5 | 服务制度、作业规程、变更记录 |
| XLSX | 4 | 参数、部件兼容、故障代码、服务价格与条件表 |
| PPTX | 3 | 产品培训、故障路径、版本发布说明 |
| HTML | 2 | 帮助中心与升级公告 |
| Markdown | 2 | 技术 FAQ 与排查说明 |
| TXT | 1 | 一份明确日期和设备信息的服务记录 |
| CSV | 1 | 工单记录或部件目录 |
| 独立 PNG/JPG | 2 | 连接示意图、告警面板说明 |
| 合计 | 36 | 各文档必须具有独立业务用途 |

16 份 PDF 目标总量为 180～240 页；长手册与短公告混合，页数不作为独立质量证明。最终按事实覆盖、图表质量、引用可验证性和重复率验收，不靠重复段落或空白页补足数量。

PDF 必须覆盖：单栏、双栏、长段落、嵌套编号、多级标题、页眉页脚、目录、跨页段落、普通表格、合并表头、跨页长表、横向页面、脚注与单位、曲线图、结构图、流程图、文字嵌入图、扫描页、中英文型号与符号、新旧版本。

材料应有“普通 / 单一难点 / 多难点叠加”三个层次，避免全部为故意破坏的极端文档。

验收要求：

1. 先建立事实底稿和版本关系，再制作文档及题目，避免互相矛盾的随机数据。
2. 每份资料必须有完整目的、适用范围、主体内容和必要条件。
3. 表格和图示必须承载真实可提问的信息，不用无关装饰图冒充多模态样例。
4. 图示、表格、正文中的相同参数必须交叉校验。
5. 训练用虚构内容有显著说明，不作为真实设备操作依据。
6. 模型生成的首页装饰图不作为知识库事实来源。
7. 输出语料清单：格式、页数/工作表数、难点、产品族、版本、文件摘要和覆盖题目。
8. DocMind 未出错的样例如实记录，不制造错误以配合课程故事。

## 5. 评估集 taxonomy

固定 200 条；140 条开发集、60 条保留测试集，开发集中选 20 条冒烟题。

一个题目只有一个主任务类别；其他维度允许多标签。taxonomy 是本课程范围的覆盖设计，不能据此声称涵盖所有企业 RAG 场景。

### 主任务配额

| ID | 主任务 | 数量 |
|---|---|---:|
| T01 | 单事实查询 | 30 |
| T02 | 条件与适用范围判断 | 25 |
| T03 | 表格查找与比较 | 30 |
| T04 | 图片/图表/流程图理解 | 20 |
| T05 | 操作步骤与故障排查 | 20 |
| T06 | 数值计算与单位处理 | 20 |
| T07 | 多证据整合 | 20 |
| T08 | 时间、版本与有效性 | 15 |
| T09 | 无依据时拒答 | 12 |
| T10 | 信息不足时澄清 | 8 |
| 合计 | | 200 |

### 正交标签

- 来源格式：PDF、DOCX、XLSX、PPTX、图片、HTML、Markdown、TXT、CSV。
- 版式难点：多栏、跨页、合并表格、脚注、扫描、旋转、图文关联等。
- 证据跨度：单块、跨块、跨页、跨表、跨文档。
- 问法：直接、同义改写、口语、缩写、错别字、隐含条件、多轮指代。
- 答案行为：直接回答、按规则计算、拒答、澄清。
- 难度：基础、中等、困难；按所需证据和推理步骤定义，不按模型是否答错定义。
- 业务属性：产品族、型号、版本、生效时间、服务区域。
- 失败阶段：运行评估后记录的诊断结果，允许多个阶段或 unknown，不能预先认定错误必然来自检索。

输出覆盖矩阵：任务×格式、任务×证据跨度、格式×版式难点、任务×答案行为。未覆盖的格子如实显示，不要求所有不适用组合都有题。

问题语料去重按底层事实/产品族/版本关系分组，避免同一事实的改写题跨开发集和测试集。保留集不用于调参；结课统一比较冻结基线与最终版本。

评估记录必须包含原始证据定位与必需回答要点；不能把解析输出自动当作真值。不可回答题说明知识库缺少什么，以及已核查的文档范围。

## 6. 前端参考的处理

参考目录：[课程根目录]/site-files

v0.9视觉材料：site-files/index.html是S2设计说明，assets/s2保存原背景与图标，screenshots保存当前界面参考。历史摄影模板已从当前视觉材料中移除。这里不包含学生业务实现。

视觉依据：S2 蓝白风格，底色 #EFFBFD、主色 #1F70FE、蓝紫渐变、半透明侧栏、白色圆角面板、底部输入框和右侧引用。使用 site-files/assets/s2 原素材；导航和组件验收见 specs/M26-S2前端整合.md。

迁移原则：

- 保留视觉语言，并改写为设备资料和售后知识场景。
- 使用 React 组件与真实状态建立文档、问答、调试、评估页面。
- 不引入S2的登录、会话或语音后端；继续使用课程现有业务接口。
- 原参考中的第三方统计脚本不带入学员项目；核心样式和图标改为项目依赖或本地资源，避免运行依赖多个远端 CDN。
- 文件上传、解析完成、入库完成和回答完成分别有真实状态，不用动画代替服务状态。
- 调试信息放入可展开面板，业务用户默认看到清晰的答案、来源和文档状态。

图片接入和学生可复制的完整 AI 指令见 ../branding/前端生成指令.md。
