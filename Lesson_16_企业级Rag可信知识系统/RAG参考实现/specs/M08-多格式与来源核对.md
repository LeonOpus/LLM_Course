# M08 / 多格式结构与来源核对

## 用户故事

作为不会Python的新手，我要在同一页分别查看DocMind解析文本和原文件结构，知道一段文字来自哪一页、哪个段落、哪个工作表或哪一行；发现差异时能留下证据，不用猜测模型出了什么问题。

## 本节新增接口

GET /api/documents/{doc_id}/source-inspection：

- 已上传即可请求，不要求DocMind成功，不改变上传/解析/入库状态。
- 返回role=source_audit、replaces_docmind=false、doc_id、source_sha256、blocks、structure、warnings、alignment及解释。
- 只读本机原文件，核对SHA与上传记录；结果保存为同目录source-inspection.json。
- 不修改blocks.json，不调用DocMind、百炼或Milvus，不作为新语料重复入库。
- 不存在的文档404；文件格式损坏、源SHA不符、解析缓存结构损坏或该扩展名无法原生核对时422。

## 统一外壳与不同来源语义

| 格式 | 原生核对能给出的信息 | 边界 |
|---|---|---|
| PDF | 页数、页尺寸points、旋转 | 不做OCR；正文依旧依赖DocMind |
| DOCX | 正文顺序、段落编号、表格编号、标题路径、合并格HTML | 不伪造固定页码；未覆盖页眉页脚、文本框、修订和图中文字 |
| XLSX/XLSM | 工作表、可见性、行范围、值/公式/格式、合并范围 | 不把第一行猜成表头；缺公式缓存标missing，存在也标present_unverified；图表另查 |
| PPTX | 幻灯片、形状ID/路径、文本与合并表格、EMU坐标 | 存储顺序不是视觉阅读顺序；组内坐标不冒充整页；图片/图表/备注另查 |
| HTML | 静态标题、段落、列表、导航、表格，XPath/可用的唯一锚点 | 不执行JS、不访问外链；源行只作起始提示 |
| MD/TXT | 原始文本与物理行范围；Markdown围栏保留内部空行 | 不读取外链图片；未闭围栏报警 |
| CSV | 表头、记录内容和真实物理行号 | 保留源空值，不自动补作者解释 |
| 图片 | 文件尺寸pixels | 不做OCR，仍需DocMind结果 |

统一块包含doc_id/type/text/locator/metadata。原生报告metadata.role=source_audit；来自DocMind的块保留自己的parser/text_origin。所有报告必须明确原文、解析内容、模型补充、作者解释的来源。

## 对齐规则

折叠空白后，按整块文本做精确匹配：unique_exact、ambiguous、unmatched。多处相等不选第一处，未匹配不猜页码；唯一相等仍是候选来源，不直接写回解析块。数量不叫准确率、召回率或RAG评分。

## 验收

- 36项阶段后端测试（原M07 20项＋原件核对11项＋接口5项）。
- 22项前端测试（原M07 14项＋来源显示8项），构建。
- Word展示正文段落和表格，Excel显示表名和范围；非法PDF页码降为块级提示。
- 实际上传D17和D23，点击核对原文件，筛选paragraph-5与B22，回查原文件。
- 实际DocMind解析后才核对parsed blocks与原文件；未执行此项保持pending。
- 36份现有业务语料的原生结构核对已在同一学生项目执行，原件字节未改变。这独立于模型效果评价：PDF只核对页信息，图片只核对尺寸，PPT图表语义仍不在原生文本读取范围；不得声称全格式云解析质量验收完成。

## 规格与材料的延续

继续使用specs/tasks.json、specs/api-contract.md和specs/acceptance.json，沿用AC-05，在additional_checks区分本地与真实DocMind对齐。M08测试用pipeline.folder(doc_id)访问临时文件，可实现为已有安全目录查询的薄封装，不要求把存储实现重写成教师版本。

prepare_m08同时提供D26第5张幻灯片预览及原PPT/图片指纹，供“4.4在图表、3.6在旁注”的读取范围诊断。预览是教学派生材料，不能作为额外业务文档入库，也不是DocMind输出。
