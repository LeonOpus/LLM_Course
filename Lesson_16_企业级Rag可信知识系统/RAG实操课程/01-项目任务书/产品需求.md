# 产品需求文档

产品名：设备知识库（内部代号 RAG 实操项目）
版本：需求 v1.0，2026-09
配套：`页面原型/index.html`（可点击原型）、`验收标准.md`、`验收题集/`

## 1. 用户与场景

| 用户 | 场景 | 最在意 |
|---|---|---|
| 售后一线（业务用户） | 客户打电话进来，边问边查 | 答案快、有出处、条件不丢 |
| 售后主管 | 抽查回答质量 | 资料不足时不能编 |
| 技术团队 | 上线前验收、上线后优化 | 每次改动能量化好坏 |

## 2. 页面清单

应用是单页应用，左侧导航五个入口。**第一期先做前两页，后三页在后续迭代补齐**，但导航从一开始就是五项。

| 顺序 | 页面 | 一句话 | 第一期 |
|---|---|---|---|
| 1 | 知识问答 | 提问、看回答、点引用看原文 | 是 |
| 2 | 知识库 | 上传、解析、入库、查看每份资料状态 | 是 |
| 3 | 检索调试 | 只检索不回答，看候选和分数 | 后续 |
| 4 | 质量评估 | 导入两次运行结果，看指标和逐题差异 | 后续 |
| 5 | 环境检查 | 看后端、数据库、云服务各自是否可用 | 后续 |

视觉按 `页面原型/` 里的样式：底色 `#EFFBFD`，主色 `#1F70FE`，蓝紫渐变背景，左侧半透明导航，白色圆角面板。素材在 `页面原型/assets/s2/`。

## 3. 功能需求

### 3.1 知识库

| 编号 | 需求 | 说明 |
|---|---|---|
| KB-1 | 上传文件 | 支持 pdf、docx、xlsx、pptx、png/jpg、html、md、txt、csv。空文件、不支持的类型要给明确错误 |
| KB-2 | 解析 | 除 csv 走本地结构化读取外，其余走 DocMind。解析是异步的：提交后先显示"解析中"，完成后才显示"已解析"，失败显示"失败"和原因 |
| KB-3 | 保留原始解析结果 | DocMind 返回的原始结果要落盘，后续可以回看，不能只留处理后的文本 |
| KB-4 | 来源定位 | 每一块内容都要能说出它来自哪份文件的哪里：PDF 是页码和坐标，Word 是标题路径和段落序号，Excel 是工作表和单元格，PPT 是幻灯片序号，图片是区域，纯文本是行范围。**不存在的定位不能编**，比如 Word 不能编页码 |
| KB-5 | 切块与入库 | 把解析结果切成片段，每段算向量存进 Milvus。入库状态和解析状态分开显示 |
| KB-6 | 文档列表 | 显示每份资料的文件名、格式、状态、块数、片段数；可以查看解析结果、下载原件、删除 |

### 3.2 知识问答

| 编号 | 需求 | 说明 |
|---|---|---|
| QA-1 | 提问 | 底部输入框，Ctrl/⌘+Enter 发送；可以选"单轮"或"带历史" |
| QA-2 | 流式回答 | 回答逐字出现；可以停止接收，停止后迟到的内容不再显示 |
| QA-3 | 引用 | 回答里的每个结论标引用编号；右侧"参考来源"卡片列出被引用的片段；点卡片看完整原文、定位，能下载原件 |
| QA-4 | 引用必须来自上下文 | 模型只能引用这次真正给它看的片段，编号不存在或摘录不是原文要拦下来 |
| QA-5 | 资料不足 | 知识库为空、或检索不到相关证据时，明确回答"现有资料不足以确认"，不用模型自己的知识补 |
| QA-6 | 澄清 | 问题缺关键条件（比如没说型号、没说订单日期）时，反问缺什么，而不是猜一个 |
| QA-7 | 带条件的计算 | 涉及费用、保修期、单位换算的问题，回答要列出用了哪些证据、哪些条件，算式可核对 |
| QA-8 | 查看检索过程 | 回答下方可展开本次的候选片段、最终上下文、参数和耗时 |
| QA-9 | 示例问题 | 空状态时给三个示例问题卡片，点了直接填入 |
| QA-10 | 临时资料 | （可选）对话里拖入一份小文件，只在本次会话用，不进知识库 |

### 3.3 检索调试

| 编号 | 需求 |
|---|---|
| DBG-1 | 输入问题和 top_k，只做检索，不生成回答 |
| DBG-2 | 显示每个候选的分数、来源、正文；开了重排时同时显示重排前后的顺序 |
| DBG-3 | 可以限定只在某几份文档里检索 |

### 3.4 质量评估

| 编号 | 需求 |
|---|---|
| EV-1 | 导入一次或两次运行导出的比较文件（JSON），在浏览器本地读，不上传 |
| EV-2 | 显示指标表，每个指标同时显示分子分母，不只显示百分比 |
| EV-3 | 逐题列表，可按"改善 / 退步 / 不变"和题型筛选，点开看两侧回答、引用、检索轨迹和评分 |
| EV-4 | 显示两侧的配置、耗时和用量，让人知道比较的是什么 |

### 3.5 环境检查

| 编号 | 需求 |
|---|---|
| ENV-1 | 分别显示后端进程、Milvus、百炼、DocMind 四项的状态；"配置存在"和"调用成功"要分开显示 |
| ENV-2 | 显示当前生效的模型名、向量维度、检索参数，不显示任何密钥 |

## 4. 检索与回答的默认参数

技术团队给的起点，后续通过验收题对照来调：

| 参数 | 起点 | 说明 |
|---|---|---|
| 向量模型 | text-embedding-v4，1024 维 | 换向量模型意味着全部重新入库 |
| 生成模型 | qwen-plus，temperature 0 | |
| 候选数 top_k | 10 | 检索最多取回多少片段 |
| 最终上下文 final_k | 5 | 最多给模型看多少片段 |
| 上下文正文预算 | 6000 字符 | 给模型的证据正文总长度上限；后续会对照 30000 |
| 对话历史 | 最多 6 条、6000 字符 | 和上面的证据预算是两回事 |

## 5. 非功能需求

- 密钥只在本机 `.env`，不进代码、不进前端、不进日志。
- 所有状态都是真实状态：解析中就是还没解析完，失败就显示失败，不用动画和假数据糊过去。
- 每次问答留一条完整记录：问题、参数、候选、上下文、回答、引用、耗时，供评估和排查。
- 一台 macOS 或 Windows 11 开发机能跑起来：后端 8000 端口，前端 5173 端口，Milvus 走 Docker。
