# 本次问题排查记录

## 问题 1：传入 --host 127.0.0.1，端口实际监听所有地址

- **现象**：使用现有 vLLM 服务命令启动后，参数显示 `host=127.0.0.1`，但 `ss -ltn` 显示 `0.0.0.0:18101`。服务未配置 API 鉴权，发现后立即停止。
- **排查**：查看本机 vLLM API 服务代码发现，服务提前执行 `sock.bind(("", args.port))`，随后将这个 socket 的 fd 传给 Uvicorn。预绑定的 socket 决定了监听地址，后续的 host 参数没有改变它。
- **处理**：项目的 `serve_loopback.py` 只在当前进程针对指定端口拦截该类绑定，替换为 `127.0.0.1`；没有修改共享环境的 vLLM 源码。运行时仍需检查 `ss` 的实际结果。
- **回归**：重启后 `ss` 显示 `127.0.0.1:18101`；健康、普通及流式 API 测试成功。
- **边界**：这是本机现有开发版环境的具体表现，不能推断所有 vLLM 版本都如此；该包装只为本机教学测试，并不等于生产安全方案。

## 问题 2：健康接口正常，但生成接口报 500

- **现象**：服务 `/health`、`/v1/models` 正常；生成请求返回 500，流式请求连接提前结束。
- **日志证据**：异常路径进入 `outlines` 解码后端，报 `ModuleNotFoundError: No module named 'pyairports'`。`pip show pyairports` 有元数据记录，但实际模块不能导入；仅凭这点不能判断为何环境会处于此状态。
- **处理**：本机已有的 `lm-format-enforcer` 后端可以导入，启动脚本将 guided-decoding backend 改为它。没有安装新包，也没有修改共享 conda 环境。此项目仅测试普通文本生成，不声称 JSON schema 等约束生成能力已验证。
- **回归**：等待健康接口就绪后重跑接口用例，6 项通过，其中包含非流式和流式生成；随后压测预热与请求也实际运行。
- **补充**：切换后曾过早运行一次测试，因服务尚未就绪全部连接失败。确认健康接口就绪后重跑，不能把“连接失败”误认为模型精度或性能问题。
